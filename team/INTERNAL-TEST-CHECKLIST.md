## 0. 为什么需要这份清单

内测四场景的**后端逻辑已全部打通**（见 §3 实测证据），但有两个**配置性前提**：
**漏开 flag 会导致「接口成功、界面空白」**——这类故障比报错难排查得多。

本地实测已证实：**`LINEAGE_ENABLED` 未开时**，老师入社区会返回
`lineage: null` + warning「师门未创建（lineage_disabled）」，且**老师端学生列表恒为空**
（读路径强制按 `lineage_id` 过滤，而写入路径没写该列时查不到）。

## 1. 启动前：环境变量（**内测必须全开**）

后端 `backend/.env` 或进程环境：

| 变量 | 必填值 | 不开启的后果（实测） |
| :-- | :-- | :-- |
| `DEEPSEEK_API_KEY` | 真实密钥 | AI 整理不可用。**后端仍可启动**（D-051 惰性化后不再崩），但转写/草案退化为降级骨架 |
| `LINEAGE_ENABLED` | `on` | 🔴 **师门不建 → 老师端看不到任何学生**；邀请入社区的学生查不出来 |
| `TEMPLATE_API_ENABLED` | `on` | 四类模板接口 404，模板配置不可用 |
| `AGENT_STAGE_ENABLED` | `on` | 智能体五阶段接口 404，阶段卡不渲染 |
| `LEARNING_ENABLED` | `on` | 学习闭环三端点 404；**阶段闸 off 时学习统计恒返回空骨架**（跨 flag 耦合） |
| `SEAL_ENABLED` | 按需 | 封存面板整卡不渲染（内测可不开） |
| `EXPORT_ENABLED` | 按需 | 学生导出 404（内测可不开） |
| `CRYPTO_ENABLED` | 按需 | 加解密四端点 404（内测可不开） |
| `REFERRAL_ENABLED` | 按需 | 引荐链接口 404（内测可不开） |
| `WITNESS_USE_MOCK` | 保持 `1` | D 板块见证页返回假数据（内测不涉及，保持默认即可） |

> **flag 取值口径**：`on` / `1` / `true` / `yes` 均可（逐服务一致，见各 `*_enabled()`）。
> **flag 读取时机**：多数在**每请求现读**，但 `witness_router` 的 mock 开关是**模块级读取**（改后需重启）。

## 2. 启动步骤

```bash
# ① 后端（工作目录 = backend/）
cd backend
python -m uvicorn main:app --host 127.0.0.1 --port 8000

# ② 前端
cd frontend
npm run dev        # 开发；或 npm run build 出 dist
```

**数据库**：默认 `backend/zhiheng.db`。`init_db()` 建业务表，**迁移链建 `lineage` 等表** ——
两者都要跑（生产启动路径已自动串起来；手工起库时注意先 `init_db` 再 `alembic upgrade head`）。

### 3.1 界面验收步骤（须人工在浏览器走一遍）

| # | 场景 | 操作 | 期望 |
| :-- | :-- | :-- | :-- |
| 1 | **老师入社区** | 老师端 → ⚙️ 设置 → 🧑‍⚕️ 老师入社区 → 填姓名 → 入社区 | 提示「已入社区」；老师列表出现该人；同名师门 `lin-<slug>` 建成 |
| 2 | **邀请 ≥3 学生** | 管理页 → 🎫 生成邀请码 → 复制码 → 学生端持码加入（3 次） | 老师端「👥 学生管理」人数 = 3 |
| 3 | **预约面诊** | 设置页 → 就诊形式选「🏥 当面诊疗」→ 填日期时间原因 → 提交 | 预约列表出现；落库 `is_remote=0` |
| 4 | **预约远程** | 同上但选「💻 远程问诊」 | 落库 `is_remote=1` |
| 5 | **非预约面诊** | 直接转写（不经预约）→ 生成草案 → 签字 | 病历 + 随访生成；**不得凭空产生预约记录** |
| 6 | **核心闭环** | 学生录音/上传 → 老师改草案 → 签字 | 学生端见病历与随访 |
| 7 | **切换老师不串台**（D-070） | 以老师 A 打开诊室/管理（让列表有数据）→ 点老师选择器切到老师 B | **B 的页面不得短暂显示 A 的草案/病历/预约/待办**；应立刻清空再加载 B 的数据 |

### 3.2 已知限制（内测期接受）

| # | 限制 | 说明 |
| :-- | :-- | :-- |
| 1 | **无身份认证** | `teacher_name` / `student_name` 由请求方自报；只防误操作、不防直连伪造（TD-008）。内测限受信环境 |
| 2 | **无真实登录** | 身份源自「老师/学生列表第一个」+ 角色切换按钮（D-059）；非账号体系 |
| 3 | **转写/病历无「远程 vs 当面」标记** | `appointments.is_remote` 有，但转写与病历上没有（D-056） |
| 4 | **前端无自动化测试** | 改动的验证上限 = `tsc` + 构建 + 模块加载 + 后端实启（D-060） |
| 5 | **归档/监护/守护/上链未接** | 按范围暂缓（见 goal 的暂缓清单） |
