### 完成

#### ① 负余额：CTO 上一轮判断**被推翻**，已采纳并补强推理

**我上一轮的错**：裁定「欠费 = `balance <= 0`，禁止负余额是正确的业务语义」。

**发起人纠正成立。** 我补上了「为什么对」——这比纠错本身更重要：

| 步 | 推理 |
| :-- | :-- |
| 1 | 「按次付费」的学生 = **先获得服务，再付款** |
| 2 | 服务发生时，此次成本**必须记一笔**（否则这次服务的账凭空消失） |
| 3 | 记了这笔 → 余额**必然暂时为负**（尚未收到供养） |
| 4 | 余额为负 = **「已服务、未收款」** = 这正是「欠费」要表达的事实 |
| 5 | 若拦截负余额 → 账**无法记** → 智能体**看不到欠费** → **无法生成催缴请示** |

→ **故：禁止负余额不是「正确业务语义」，而是让智能体丧失判断依据。**

**且自洽于 v2.1 §6.3.6（L1805）**：「供养在服务之后发生」→「先记成本、余额为负、待供养到账后充电」正是镜像记账的自然形态。

**须改的实现点**（已写入大纲 P-303）：

| 位置 | 现状 | 改为 |
| :-- | :-- | :-- |
| `database.py:1398` | `if balance + amount < 0: rollback; return {"ok": False, "error": "余额不足"}` | **放开负余额** |
| `backend/test_api.py` | 断言「余额不足不扣款」 | 改为断言**负余额被正确记录** |
| `agent.py:624` | `if balance >= low_balance: continue` | 新判据（见下） |
| `agent.py:621–622` | 无账户 → 跳过扫描 | **按次付费学生须先建档** |

#### ② ⚠️ 但放开负余额带出新问题 —— 已提出 **T-25**

若判据是「`balance < 0` 即欠费」→ **每一次按次付费都立刻触发催缴**，而按次付费是**正常模式**。

**CTO 拟定：引入「信用额度」`credit_limit`**

```
欠费判据 = accounts.balance < -credit_limit
  · credit_limit = 0 → 纯预存制（必须先充值后消费）
  · credit_limit > 0 → 按次付费（允许欠到该额度）
```

→ 把「**正常按次付费**」与「**真正欠费**」区分开；且 `credit_limit` 本身**可入 `teacher_rules`**（老师自定）。
→ 落点两选项：(a) 只放 `teacher_rules`（老师一个值）/ (b) **按学生设**（信任度不同）。
→ **CTO 倾向 (b)**。标为 **T-25 待裁**。

#### ③ 账户合并：CTO 裁定**合并到 `accounts`**（T-20 结案）

| 项 | 决定 |
| :-- | :-- |
| 权威表 | **`accounts`** |
| 账本 | **`transactions`**（含 `balance_after` → 可回溯） |
| `points_accounts` | **停止写入**；旧接口读它时转发到 `accounts`；遗留消费完后视为废弃 |
| 打卡得分 | `add_points`（写 `points_accounts`）→ **改走 `recharge_account`**（写 `accounts` + `transactions`） |
| 「积分」=「康币」 | ✅ 同一物 → **术语统一为「康币」** |
| 迁移 | 与 P-102 / P-302 **同批 `0009`**；冲突**取 `accounts` 值 + 迁移日志记差额**，不静默改数 |

**理由**：两套并存的唯一后果是「打卡得分」与「预存余额」**是两个数**，门规读哪套都漏一半。
