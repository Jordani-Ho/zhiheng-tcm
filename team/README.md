## 一、团队角色

| 角色 | 形式 | 职责 | 不做 |
| :-- | :-- | :-- | :-- |
| **发起人** | 真人 | 产品决策、优先级、审阅、拍板 | — |

## 二、三条工作流

### 工作流 1：设计 → 执行

```
知衡（设计）
  │
  ├─ 产出设计文档 → docs/
  ├─ 产出决策记录 → team/decisions/
  └─ 产出执行指令 → 对话中（发起人转达）
        │
        ▼
发起人
  │
  └─ 贴指令给 DSH
        │
        ▼
DSH
  │
  ├─ 执行
  └─ 写 worklog → team/worklogs/
        │
        ▼
发起人
  │
  └─ 把 DSH 回报贴回知衡
```

### 工作流 2：会话启动

**每个新对话/会话的第一句**：

```
读 team/README.md
读 team/roles/[你的角色].md（如有）
读 team/worklogs/[你的角色].worklog.md（如有）
恢复上下文，告诉我上次做到哪。
```

### 工作流 3：会话收尾

**每次重要产出后**，追加到 worklog：

```
## YYYY-MM-DD

- 完成：XXX
- 待办：YYY
- 待发起人决策：ZZZ
- 下次启动时读：team/handoffs/[本次 handoff 文件]
```

## 七、纪律

### 对所有角色

1. **一角色一职责**——不越界。
2. **文档有状态，对话无状态**——重要信息写进文件，不靠对话记忆。
3. **交接必留痕**——handoff 文件不省略。

### 对知衡（设计）

1. 只碰 `docs/` 和 `team/`
2. 不写业务代码
3. 不跑命令
4. 不 commit

### 对 DSH

1. 工作目录限于 `D:\projects\zhiheng-tcm`
2. 每次执行完写 worklog
3. 不做产品决策——遇到需要决策，停下，写 handoff，回报发起人
4. 不 commit（除非发起人明确授权）
5. 遇到不确定：**先读再问，不猜**
