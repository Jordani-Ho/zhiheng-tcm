## 0. 使用说明

### 0.1 什么算「重大决策」

满足任一条即应登记：

- 改变了**产品范围**（做什么 / 不做什么）
- 改变了**跨板块契约**（表结构、接口、事件口径）
- 使某个已交付物**作废或变更语义**
- 需要**发起人**拍板的产品判断
- 对外承诺（白皮书条款）的解释

### 0.2 每条决策的字段（对齐 `知衡团队重构.md`「建立决策日志」要求）

| 字段 | 含义 |
| :-- | :-- |
| 决定了什么 | 可执行的结论，不含歧义 |
| 决策人 | 发起人 / 知衡（CTO） |
| 为什么 | 依据哪条白皮书原则或哪个事实 |
| 风险 | 该决策引入什么风险 |
| 重新评估条件 | 出现什么情况时必须回头看 |

### 0.3 编号规则

`D-<序号>`，**只追加不重排**。作废的决策不删除，改为标注「已作废，被 D-xxx 取代」——保留决策史。

### 0.4 状态标记

`✅ 生效` / `🟡 生效但有未决子项` / `⬜ 待发起人确认` / `❌ 已作废`

### D-020 · 后端鉴权提升为「内测前必须项」

| 项 | 内容 |
| :-- | :-- |
| **决定了什么** | 后端**身份鉴权**从「已知技术债（TD-008）」提升为**真人内测前的必须项**。 |
| **决策人** | 知衡 |
| **为什么** | 实测：后端**无 token / 无 session**，`teacher_name` / `student_name` 全由请求方**自报**；`lineage_read_scope` 只校「参数间一致性」，**不校「你是谁」**。→ 师门隔离**防得住**前端串门与服务端漏过滤，**防不住**直连后端伪造 `teacher_name` 读他人数据。而白皮书承诺「学生自己的完整档案由学生智能体统一保管，老师只查看自己名下部分」——**现隔离强度不足以支撑该承诺**。 |

| **风险** | 加鉴权 = **全库架构级改造**（所有路由），工作量大、回归面广。可选低成本路径：先做**签名/令牌**而非完整账号体系。 |
| **重新评估条件** | 若第一次落地仅在**单机单人**环境验证（无网络暴露）→ 可降级为「内测前」而非「第一次落地前」。**本项请发起人确认适用时点。** |
