#### D1：四类模板完整版

对齐：白皮书 2.0 第三章。

- 统一 `Template` 模型：`id, type, lineage_id, teacher_id, name, schema_json, version, parent_template_id, status, created_at, updated_at`。
- `type` 枚举：`inquiry`、`record`、`treatment`、`prescription`。
- `status`：`draft`、`active`、`archived`。
- 老师智能体只能使用 `active` 模板生成草案。
- 每次生成记录 `template_id + version`，历史病历不受模板变更影响。
- 前端老师端 4 页签增加模板配置入口。

#### D2：老师智能体五阶段

对齐：白皮书 2.0 第二章 2.3.4、2.3.5。

- `agent_stage` 枚举：`observation`、`learning`、`apprentice`、`assistant`、`authorized`。
- 权限矩阵在后端 service 层强制，前端只展示。
- 每次老师修改 AI 输出，写入 `agent_learning_events`。
- 一致率计算：模板匹配度、病历修改一致率、问诊偏好一致性。
- 升级由系统计算指标，老师确认后生效。降级可老师手动，也可规则触发。
- 授权期可生成预处方，但永不自动发送。

#### D3：学习闭环

对齐：白皮书 2.0 第五章 5.3。

- 事件流：`template_configured` → `draft_generated` → `draft_modified` → `learning_event_emitted` → `agent_updated`。
- 所有事件写入 `agent_learning_events`，本地哈希链：`prev_hash + payload_hash`。
- 老师修改草案时，记录差异：字段级 diff、措辞变化、证型变化、方剂变化。
- 学习结果更新老师智能体的统计指标，不直接改模型权重。
- 阶段一不做模型微调，只做规则统计与模板偏好。

#### D4：多师管理

对齐：白皮书 2.0 第四章 4.2。

- 新增 `lineage`（师门）实体：`id TEXT PRIMARY KEY`（`'lin-' + slugify(teacher_name)`，与 `templates.lineage_id` 同构）、`name`、`owner_teacher_name`、`description`、`status`、`created_at`、`updated_at`。阶段一一师一门。
- `student_lineage` **不新建表**：升级既有 `patient_teachers` 为事实上的 `student_lineage`（概念名 = `student_lineage`，实现名 = `patient_teachers` 升级版）：补 `lineage_id` 列，`status` 复用既有 `active` / `inactive` 语义（退出 = `inactive`，不删数据）。学生可属于多个师门。

## 4. 阶段一技术决策

1. **技术栈不换。** 继续 React + Vite + TS / FastAPI + SQLite + LangGraph / DeepSeek API。
2. **引入 Alembic。** 所有 schema 变更可迁移、可回退。
3. **权限硬约束在后端。** AI 永不诊断、永不开方、永不签字，在 service 层强制。
4. **`lineage_id` 作为隔离键。** 所有师门数据带此键，查询强制校验。
5. **本地哈希链预留。** 事件日志用 `prev_hash + payload_hash`，为未来上链准备。
6. **数据不上云。** 阶段一继续本地 SQLite，不引入云存储。
7. **模型不锁定。** 智能体逻辑与 DeepSeek API 分离，为本地模型留接口。
8. **导出格式预留。** 阶段一实现 JSON 导出，为阶段二数据主权准备。
9. **测试要求。** 后端 pytest，前端 vitest。权限矩阵必须有单测。
10. **不设出师。** 学生可自行退出。白皮书 2.0 2.4.5 的“毕业”表述暂不修改，执行计划按“降低提醒频率，不产生认证”处理。
11. **默认字库：繁体汉字，古字优先。** 前端 UI 文案、AI 生成内容、注释、术语，默认繁体古字。用户输入接受简繁混合，展示统一为繁体古字。炁（先天）与氣（后天）按语义区分，禁止无脑替换。术语表见附录 A。
12. **治理见证入口（只读总览）**：9 席治理见证人（2 永久 + 7 推举）。跨师门、跨老师、跨学生的只读总览入口。单向输出，禁止任何写操作（数据库 RO 连接 + API 仅 GET）。常规访问记审计日志；证据模式下生成带哈希快照。永久席位不可转移，承担者离世/淘汰 → 休眠。推举席位 ≥5 席活跃才合法运转。落地时机：**Epic 4 之后**（原写「Epic 5 之前」——Epic 5 已废除，见 D-017），独立子任务。**实测现状（2026-10-04）**：M2 只读入口 + M4 哈希快照已实现；M1 席位机制 / M3 证据模式 / M5 接口契约 未开工；依 **D-015**，M1 暂不启动。
