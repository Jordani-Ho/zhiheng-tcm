## 1. 施工顺序（已定，来自 v0.4 §11）

### 1.1 五子项依赖

```
引荐链 ──→ 存活门限
   │
   ├──→ 协议底线
   │
   └──→ 段位
   
康币（独立）
```

### 1.2 建议顺序

| 序 | 子项 | 依赖 | 理由 |
| :-- | :-- | :-- | :-- |
| 1 | 引荐链 | 无 | 地基，其他四项依赖 |
| 2 | 存活门限 | 引荐链 | 依赖引荐链，独立于其他 |
| 3 | 协议底线 | 引荐链 + 封存接口（待 B4） | 见 §3.1 |
| 4 | 段位 | 引荐链 | 依赖引荐链，独立于其他 |
| 5 | 康币 | 无 | 独立，可最后做 |

### 1.3 与阶段四衔接（来自 v0.4 §11.3）

- 所有新增表预留 `chain_ready` + `chain_hash`
- 所有封存 / 解封动作预留 `evidence_hash`
- 阶段四只补上链逻辑，不改数据结构

**与 D 板块只读预留**：

四个只读接口登记（不在 C 板块实现）：

```
GET /api/governance/readonly/referrals      # 引荐链只读
GET /api/governance/readonly/seals          # 封存记录只读
GET /api/governance/readonly/levels         # 段位变更只读
GET /api/governance/readonly/kangbi         # 康币账本只读
```

## 2. 验收标准（已定，来自 v0.4 §12）

### 2.1 各子项验收条件

| 子项 | 验收条件 |
| :-- | :-- |
| 引荐链 | 老师引荐老师、学生引荐亲友全流程可走通；额度限制生效；信誉降级触发 |
| 存活门限 | 90 天未达标自动转不活跃；再 90 天自动下线；状态变更写入 `agent_stage_log` |
| 协议底线 | 四条底线可上报；封存动作与 B4 对齐；证据哈希生成正确 |
| 段位 | 老师可评定；多师汇总展示正确；与阶段字段不混用 |
| 康币 | 社区外交易可确认；账本记录正确；不接支付通道 |

### 2.2 整体回归要求

- `lineage_id` 不重定义，Epic 4 测试全部通过
- `agent_stage_log` 写入通道不冲突，Epic 2 测试全部通过
- 封存动作与 B4 语义对齐，B4 测试全部通过
- 阶段字段（Epic 2）与段位字段（C 板块）不互相影响
